静态网站。请将 `index.html`、`paper.js`、`review.js`、`runner.js`、`sample-frame.html`、`python-refs.js`、`sw.js`、`icon-192.png`、`icon-512.png` 和 `manifest.webmanifest` 放在同一目录，通过 HTTPS 或 localhost 访问。

- 题库版本 `2026.11.20`：71 道编程题、56 道自编基础选择题。
- 保留全部已有题号和题目字段；补充 4 组边界练习样例、6 道基础题，并明确 int / byte 题目的平台前提。

- 独立保存设置、累计统计、错题、收藏、逐次答题历史及两种题型的练习进度。
- 刷新、关闭后重新进入可恢复题目顺序、当前位置、已选答案、自评和本组结果，恢复不会再次计分。

按 T1 至 T5 依次收录 29、10、20、6、6 道。题库搜索 `202406` 可找到 2024 年 6 月的全部五题。首页四小时模拟对应 2024 年 3 月场次。

## 做一道编程题

1. 打开一道真题，可以先读本站摘要，再从题面链接核对完整条件。题库补入 201312 的第 3、5 题；首页按题位列出实际收录量。
2. 在「我的解答」写代码。C++ 和 Python 分开保存草稿。Python 可在当前浏览器运行公开样例，首次需从 jsDelivr 加载 Pyodide。代码在浏览器本地执行。C++ 请前往外部 OJ 编译和提交。
3. 拿到 OJ 判定后，可登记结果及提交编号，在复盘笔记里写下卡点。首页只统计最近登记为 AC 的题数。自评和样例结果各自独立。
4. 单题累计时间按前台练习时间估算，连续两分钟无操作暂停。整套模拟使用单独的四小时倒计时，离开页面也继续走时。

## 日常复习与备份

- 首页提供当日三题，兼顾基础、错题与进阶。没有新基础题时安排旧题复习，难题错题占用当天的挑战名额。错题本可按累计失误次数连续重做，复习组支持刷新续做。
- 首页「今日三题」显示组内位置、已作答与已跳过的题。可以从首页续做跨天保留的一组，或点「换一批」。离开进行中的复习组会先确认。已推荐的错题通常隔三天才会再次进入每日推荐，错题本随时可练。
- 整套模拟计时期间，从模拟卡进入曙梦 OJ 作答。站内练习入口在交卷或四小时结束后恢复。
- 自编选择题按答题明细安排间隔复习。统计页分列首次、重复作答，答题历史可按日期或题目检索，也可以直达末页。
- 首页提供当前档案的导出入口和上次发起下载的时间提醒。创建、改名与删除在「我的」中操作。删除前可先导出；删除迁移来的档案也会删除该档案的旧迁移副本。
- 公开整套模拟选用 2024 年 3 月的五道题，五题均可站内练习，也可在第三方 OJ 提交并手动登记各题得分。

## 手机与离线使用

联网打开网站后，「我的」会显示离线题库是否已就绪。之后同一网址可离线打开题库、查看 C++ / Python 参考、保存草稿和学习记录。首次运行 Python 需要下载运行环境，建议联网使用。手机首页顶部点「安装到手机」。支持直接安装的安卓浏览器会弹出系统确认框；也可在「我的」查看 Chrome 菜单步骤和 iPhone 添加方法。更新应用资源时同步更新 `sw.js` 中的缓存版本。

直接双击 HTML、本机 HTTP 和线上 HTTPS 各自使用独立的网站存储。切换访问方式前先导出档案，再到目标网址导入。
    
## 本地档案的使用范围

档案属于当前网站、设备及浏览器，不是带密码的账号。共用浏览器的人能够切换查看不同档案；手机和电脑不会自动同步。更换浏览器或设备前请导出备份。清除网站数据会删除本地档案。

请通过 HTTPS 使用网站，或在开发时使用 localhost。档案采用浏览器 Web Locks 协调多标签页写入，需要支持 Web Locks 和 `crypto.randomUUID` 的现代浏览器。不支持时会提示并停止初始化，不会覆盖旧记录。

同一个档案只允许一个标签页编辑，其余标签页只读；不同档案可以在不同标签页同时使用。每个标签页固定自己的用户 ID，新窗口默认选中最后使用的档案。只读页关闭另一编辑页后可点“重新读取档案”接管。

## 存储与兼容

旧版键 `csp_prep_app_v1` 保持原样作为迁移副本。升级时通过一次性迁移锁创建“原有学习档案”，迁移标记为 `csp_legacy_migration_v2`，刷新或清空当前档案后不会重复导入旧记录。

每个新档案单独保存于 `csp_profile_v2:<UUID>`，不使用共享的全用户学习数据对象。记录结构为：

```json
{
  "schemaVersion": 2,
  "user": {"id": "UUID", "name": "档案名称", "createdAt": "ISO 时间"},
  "revision": 1,
  "updatedAt": "ISO 时间",
  "data": {
    "settings": {}, "daily": {}, "wrong": [], "mastered": [],
    "done": [], "solved": [], "qstat": {}, "lastVisit": "",
    "favorites": [], "history": [], "progress": null
  }
}
```

原有 `data` 字段语义保留。新增字段：

- `favorites`：稳定题号列表。
- `history`：含事件 UUID、题号、题型、实际选项或自评、是否正确、时间、题目标题和题库版本。旧累计记录不会被虚构成逐次历史。
- `progress`：最后页面、编程题及选择题的题号顺序、当前位置、揭晓状态和本组统计；恢复时校验题号和状态。计时起点不落盘，关闭或后台时间不计入学习。

`csp_active_profile_v2` 在 localStorage 中保存最后选中的档案，在 sessionStorage 中固定当前标签页档案。切换前结算当前档案时长并保存；保存失败会阻止切换，页面提示可导出备份或重试。

保存由 `writeProfile` 统一写入当前 ID 的键，并校验原始快照未被外部修改。其他档案的数据键不参与这次写入。学习档案锁从加载持续到切换、离开页面；版本计数是本地写入版本，不充当跨设备冲突解决方案。

## 导入、清空与异常恢复

- 新版备份导出包含用户标识及完整学习数据，仍兼容旧版纯学习数据 JSON。
- 导入前校验内容，明确提示将替换哪个档案。只替换当前档案的学习数据，不采用备份中的用户 ID 作为写入目标，不覆盖其他用户。
- 文件异步读取期间切换了档案，会取消该次导入，包括切走后又切回原档案。
- 清空只清除当前档案的学习数据，保留当前身份和其他档案；不删除旧版迁移副本。
- 读取到损坏的原记录时暂停写入，保留原文用于导出恢复。旧版损坏内容保存在原键和迁移档案的 `recoveryRaw` 中。
- 空间或权限不足时不会显示保存成功。可导出当前内存中的记录，恢复存储条件后重试保存。重新读取前若有未保存改动会提示。

## 样例修正记录

题库版本 `2026.11.16.3` 修正了两道题的样例，另加了一道启动校验。**题面、题意与参考代码均未改动，题号未重排。**

### Q26 归一化处理（CCF CSP 202206-1）

原状态：该题有 3 组样例，其中「样例 2」与「样例 3」的**输入完全相同**（`2` / `1 3`），期望输出却一个写作 `-1` 与 `1`、另一个写作 `-1.0000000000` 与 `1.0000000000`。等于同一组数据给出两个互斥的答案。

成因：样例 1、2 写在 `BANK` 定义里，样例 3 是后续通过 `BANK.find(...).samples.push(...)` 追加边界练习时补的，**追加时没有检查输入是否已重复**。

另一个问题：参考代码使用 `cout << fixed << setprecision(10)`，只会输出十位小数形式，**不可能输出 `-1` 这种整数写法**。数值上 -1 与 -1.0000000000 相等，但照着样例格式抄会误导读者。

处理：
- 内置样例 2 的期望输出改为 `-1.0000000000` / `1.0000000000`，与参考代码一致。
- 追加的那一条换成一个输入不重复的边界用例 `4` / `-1 1 -1 1`（均值为 0、方差为 1），期望输出为 `-1.0000000000` / `1.0000000000` / `-1.0000000000` / `1.0000000000`。
- 修正后该题 3 组样例输入两两不同，格式统一。

### Q28 现值计算（CCF CSP 202212-1）

原状态：样例 2（输入 `1 0.5` / `-100 150`）期望输出写作 `0`，但参考代码用 `setprecision(10)`，实际输出 `0.0000000000`。

处理：期望输出改为 `0.0000000000`。

### 新增启动校验

`validateBank()` 增加一条规则：**同一道题的样例输入（去首尾空白后）不得重复**，重复则抛错并阻止初始化。这样以后再追加边界样例时，重复会被当场拦下，而不是等人在页面上看到两个矛盾答案。`tests/bank.cjs` 同步加了同样的断言。

### 已验证

- `node tests/bank.cjs`：96 题结构校验通过（含本次新增的重复样例断言）。
- **样例与参考代码的逐字比对，由独立的 `verify-samples.sh` 完成，不经 `tests/bank.cjs`。**
  该脚本解压题库、用 g++ 编译全部 40 份参考程序、再对 68 组样例比较。比对规则对**输入侧与期望侧施加完全相同的规范化**：删除 CR、删除每行行尾空白、忽略文本末尾空行，之后要求整段字符串相等（行内空白与空行位置不忽略）。
  修补后的结果：`逐字一致: 68 / 68`，退出码 0；在修补前的代码上运行同一脚本：`逐字一致: 66 / 68`，退出码 1，报出的正是 `q26_1` 与 `q28_1`。
- 之所以要单独写这个脚本：`tests/bank.cjs` 在设置 `CXX` 时也会编译并跑样例，但它按空白切分、把 token 转成数字后用 `1e-4` 容差比较，**格式差异会被容差吃掉**，所以它在修补前后都会照常通过，无法用来发现或在修补后证明这两处问题。

```shell
bash verify-samples.sh                    # 用 PATH 里的 g++
CXX=/path/to/g++ bash verify-samples.sh   # 指定编译器
```

（脚本在仓库里以可执行位提交，`./verify-samples.sh` 也可直接运行；写成 `bash verify-samples.sh` 可避免检出时丢掉执行位导致的权限错误。）

## 题库维护

继续使用 `BANK` 和 `CHOICE`，无需调整现有结构。编程题使用正整数 ID；选择题使用 `c` 加数字的 ID。已有题目不得复用或重新编号。

- 编程题必须有类别、来源、标题、限制、题意、输入输出格式、样例、思路和参考代码。
- 选择题必须有题干、4 个不重复选项、从 0 开始的正确答案索引及解析。
- 页面启动执行 `validateBank()`，缺字段、重复 ID 或答案索引越界会阻止初始化并给出提示。
- 当前样例及参考代码是本地练习材料；本地测试通过不等于官方评测通过。
